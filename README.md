# 하루 · 나의 첫 일본어

일본어 완전 입문자를 위한 모바일 중심 웹앱입니다. 히라가나 10글자와 기본 인사말 4개를 소리·선택 문제·직접 입력·간격 반복으로 배웁니다. 첫 버전의 범위는 브라우저에서 혼자 학습하는 흐름이며 AI API, 로그인, 서버, 배포는 포함하지 않습니다.

## 학습 범위

| 단원          | 학습 내용                                        | 직접 입력 문제        |
| ------------- | ------------------------------------------------ | --------------------- |
| 히라가나 あ행 | あ・い・う・え・お                               | 한글 발음 또는 로마자 |
| 히라가나 か행 | か・き・く・け・こ                               | 한글 발음 또는 로마자 |
| 기본 인사말   | おはよう・こんにちは・ありがとう・おやすみなさい | 한국어 뜻             |

단원당 약 5분을 목표로 하며, あ행 → か행 → 인사말을 추천합니다. 원하는 단원부터 시작할 수 있고, 홈에서는 아직 마치지 않은 단원을 추천합니다. 인사말은 모르는 글자가 있어도 소리를 듣고 표현째 익히는 단계입니다.

## 개발

Node.js 24와 npm을 사용합니다.

```sh
npm ci --cache=/tmp/test-jp-npm-cache
npm run dev
```

기본 개발 서버 포트는 5173입니다. 글꼴은 기기의 시스템 글꼴을 사용하며, 앱 실행에 외부 API나 비밀 키가 필요하지 않습니다.

## 검증

```sh
npm test
npm run build
npm run test:e2e
```

단위 테스트는 정답 판정, 복습 일정, 저장 오류, 기존 기록 호환, 콘텐츠·음원 해시와 단원 연결을 검증합니다. E2E 테스트는 데스크톱·모바일 Chromium에서 세 단원 학습, 문자와 표현을 섞은 복습, 실제 음원 재생, 기록 복구, 한글 입력, 중도 종료와 가로 넘침을 검증합니다. 시스템 Chromium(`/usr/bin/chromium`)을 우선 사용합니다. 다른 경로는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정하거나 `npx playwright install chromium`으로 브라우저를 설치하세요.

빌드된 앱을 확인하려면 `npm run preview`를 실행합니다. 개발·미리보기 서버는 클라우드 환경을 다시 시작하면 재실행해야 합니다.

## 학습과 기록

- 모양·발음·쓰임 → 단원 내 선택 문제 → 선택지 없는 직접 입력 순서로 학습합니다. 복습은 단원과 무관하게 복습 시각이 된 항목을 모아 직접 입력으로 진행합니다.
- 한글 발음(아·이·우·에·오)과 로마자(a·i·u·e·o)를 허용합니다. 앞뒤 공백·영문 대소문자·전각 영문·분리된 한글 자모를 정규화하며, 빈 답은 제출하지 않습니다. 일본어 글자를 그대로 옮기거나 여러 답을 나열하는 것은 정답이 아닙니다.
- 인사말은 발음 대신 뜻을 답합니다. 예를 들어 ‘ありがとう’에는 ‘고마워요’·‘감사합니다’를 허용합니다. 명시한 동의 표현과 일부 영어 뜻을 허용하고, 띄어쓰기와 문장 끝 구두점은 무시합니다. 자유로운 모든 한국어 문장을 의미 판별하는 기능은 없습니다.
- 직접 입력해서 처음 맞힌 글자는 다음 날, 이후 정답이 쌓이면 3일·7일·14일 간격으로 복습합니다. 선택 정답만으로 복습 단계를 높이지 않습니다.
- 틀린 글자는 즉시 복습합니다. 고쳐 맞히면 10분 뒤에 다시 복습합니다.
- `localStorage`의 `haru.progress.v1`에 답변별 기록과 최근 100회의 완료 기록을 보관합니다. 완료 전 나가더라도 이미 답한 기록은 남고, 진행 중인 세션은 처음부터 시작합니다.
- 완료 단원은 별도로 보존하므로 최근 기록이 100회를 넘어도 유지됩니다. 기존 あ행 전용 v1 기록은 삭제하지 않고 읽으며, 이전 완료 기록을 あ행으로 해석합니다.
- 복습 시각은 사용자 기기 시간을 기준으로 합니다. 백그라운드 알림은 없으며, 앱에서 15초마다 복습 목록을 갱신합니다.
- 저장 실패는 화면에 안내합니다. 브라우저 데이터를 지우거나 기기를 바꾸면 기록이 유지되지 않습니다. 동시 다중 탭 편집·기기 간 동기화는 지원하지 않습니다.
- 한글 발음은 입문 참고 표기이며, 입력 정답이 실제 발음 실력을 뜻하지 않습니다. 문제 풀이 중 발음 버튼은 답을 제출한 뒤에만 표시합니다.
- 답변 횟수에는 선택·입력 문제가 모두 포함됩니다. 새 완료 기록과 결과 요약은 직접 입력 문제의 정답 수를 표시합니다. 기존 v1 기록은 그대로 읽으며 과거 완료 기록은 이전 선택 문제 결과를 유지합니다.

## 일본어 음원

`public/audio`에 14개의 MP3(합계 약 210KB)를 포함합니다. 브라우저 일본어 TTS나 외부 음성 API 없이 재생되며, 자동 재생하지 않습니다. 다른 음원을 누르거나 화면을 이동하면 이전 재생을 멈춥니다. 음원 파일을 읽을 수 없거나 재생이 거절되면 재시도 안내를 표시하고 학습은 계속할 수 있습니다.

음원은 원어민 녹음이 아닌 Open JTalk / HTS Voice Mei 합성 음성입니다. 음소 매핑과 파일 디코딩·브라우저 재생을 검증하며, 원어민의 청취 검수는 아직 하지 않았습니다. 출처·CC BY 3.0 이용 조건은 [NOTICE](public/audio/NOTICE.txt)와 [원본 음성 라이선스](public/audio/LICENSE-mei.txt)를 참조하세요. 앱 이용 안내에서도 출처에 접근할 수 있습니다.

재생성은 [tools/generate_audio.py](tools/generate_audio.py)에 설명돼 있습니다. 생성 도구는 선택 사항이며, 일반 설치와 앱 실행에는 필요하지 않습니다. `manifest.json`은 생성 파일의 SHA-256과 글자·음소 대응을 기록합니다.

## GitHub Pages 배포

`.github/workflows/pages.yml`은 `main`에 푸시할 때 단위·브라우저 테스트, `/TEST_JP/` 경로의 프로덕션 빌드와 검증을 거쳐 GitHub Pages에 배포합니다. GitHub Actions의 기본 토큰을 사용하며 별도 API 키는 필요하지 않습니다. 저장소 Settings → Pages → Source는 **GitHub Actions**로 설정해야 합니다. 저장소 공개 범위와 GitHub 요금제에 따라 Pages 사용 가능 여부가 달라집니다.

배포 성공 후 주소는 `https://leein09.github.io/TEST_JP/`입니다. 주소가 실제 응답하기 전까지 배포 성공으로 간주하지 않습니다. 아이폰 Safari에서도 이 주소를 사용하세요. 학습 기록은 기기·브라우저별로 별도로 보관되며 자동 동기화하지 않습니다.

배포 경로를 로컬에서 확인하려면 다음 명령을 순서대로 실행합니다.

```sh
BUILD_BASE_PATH=/TEST_JP/ npm run build
npx playwright test --config=playwright.pages.config.ts
```

일반 로컬 개발은 `npm run dev`를 사용합니다. 다른 저장소 이름으로 이전하면 워크플로의 `BUILD_BASE_PATH`와 Pages 검증 설정의 경로도 변경하세요.

## 구성과 다음 단계

콘텐츠·허용 답·발음 음소는 `src/curriculum.json`, 단원 순서는 `src/content.ts`, 일정·저장은 `src/progress.ts`, 정답 판정은 `src/reading.ts`에 있습니다. 콘텐츠를 수정하면 대응 음원도 재생성하고 검증하세요.

남은 검토는 실제 입문자의 사용성 피드백, 음성·교육 내용의 일본어 교육 전문가 검수, 실제 iOS/Safari·Android에서의 청취와 키보드 확인입니다. Chromium 모바일 테스트는 실제 모든 기기의 호환성을 보장하지 않습니다. 추가 문자·문형, 계정 동기화, 자동 발음 평가나 AI 설명은 별도 범위입니다.
